## Design
- Extend document processor/worker for Markdown, retaining source whitespace and original upload bytes. Separate maxMarkdownChars=200000 from existing extracted text cap; options may only lower caps. Reuse this validation for editable UTF-8 content. Reject binary/control content and malformed encoding.
- Add attachment append and Markdown update methods through Service transactions. Reuse SHA256 as edit concurrency token, no new schema. A document update atomically changes original BLOB, extracted text, size, SHA, ticket version and audit. Include quota delta for bytes and text. All writes are admin-only in HTTP, while assigned agent context stays read-only.
- Append route POST /api/tickets/:id/attachments takes current ticket version and draft IDs. Validate full selection before binding; preserve all ticket fields. Same-ticket all-bound retry returns current detail without another audit or mutation. Foreign bindings and new duplicate hashes reject. Bound count maximum five.
- PATCH /api/attachments/:id takes text and expectedSha256. Require bound text/markdown, validated string/hash and nonempty <=200000 chars, UTF-8 byte cap, quota. On conflict 409 retain local draft. On success return full attachment and refresh parent ticket.
- Add full Markdown reader/editor modal using react-markdown and remark-gfm. No raw HTML plugin; suppress HTML and images; permit only explicit HTTP(S) links and same-document anchors. Lazy load reader to avoid growing initial panel bundle. Accessible labeled textarea, view/edit/preview/save, pending state and explicit unsaved discard handling.
- Existing Documents section shows Attach files even when empty; reuse draft upload component in modal. Disable attachment mutations while ticket fields are dirty/busy. Preserve modal draft through polling and conflicts; fetch fresh detail after successful changes. Existing non-Markdown preview/download remains.
- One-off restoration uses private manifest and stable admin API after deployment, never direct DB writes. Revalidate source hashes immediately before upload, refresh current version before append, persist source identity/SHA to ticket ID and attachment ID in the private restoration ledger after binding, check that identity first on retries (preserving subsequently edited copies and reporting divergence), otherwise skip matching bound hashes, verify downloads/context and source hashes afterward. Preserve uncertain inputs.
