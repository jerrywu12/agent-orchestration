# Independent-agent workflow research

Research date: 2026-09-13. Inspected base: `aae5a506e2464020dc5e9b9698f426b2f0077db8`. This note recommends options for the lead to scope; it does not amend the specification or authorize additional runtime behavior.

Agent Desk already has the important coordination foundation: explicit ownership, durable exclusive claims, dependency holds, isolated local worktrees, checkpointed handoffs, and a distinct awaiting-review outcome. The smallest useful improvement is a consistent task brief that follows a ticket from creation into any executor, with accessible attachments and an unambiguous project location.

## Four feasible improvements

1. **Task brief at creation.** A one-click description starter is the smallest implementation. Use headings for objective, observable acceptance checks, allowed/excluded scope, verification commands and context. A ticket can remain incomplete in backlog; existing owner/stage/dependency rules still govern claiming. Acceptance: the template survives save/reload and the same text reaches the local launch prompt and external task retrieval.
2. **Attachments usable by the assigned executor.** Persist ticket-linked metadata such as ID, filename, MIME type, size and content hash, and expose authorized retrieval. Include the manifest in the task packet without automatically copying arbitrary file contents into a prompt. Keep unavailable imported references visibly distinct from stored uploads. Acceptance: ticket creation with attachments succeeds atomically or reports retained partial state clearly; unrelated agents cannot download them; oversize/path-traversal cases fail; uploaded instruction-like text cannot alter adapter arguments or bypass claims.
3. **Project directory selection with readiness feedback.** Browse only through an administrator-controlled, bounded server-directory API or a local native chooser whose host identity is explicit. Return canonical paths; retain a manual path fallback. Show why local execution is unavailable before Start, without changing files or silently creating a repository. Acceptance: spaces and Unicode round-trip, files/missing paths are rejected, remote clients select the server's directory, and Start still uses the isolated worktree path rather than the selected checkout.
4. **Copyable start and handoff packets.** Reuse the existing ticket, execution and activity records to assemble owner/session, project/base/worktree, brief, attachments, latest checkpoint, unresolved checks and next action. Make review/delivery expectations visible; keep actual claims transactional and explicit. Acceptance: a replacement executor sees the prior checkpoint and attachment references, cannot inherit an unreleased claim, and a process exit alone remains awaiting review. Typed approval/merge verification is a separate contract decision if the lead chooses to add it.

Implement the creation/attachment/folder path first, then add packet presentation using those same records. No scheduled auto-dispatch, additional provider, broad repository indexing or autonomous stage transitions are needed for these improvements.
