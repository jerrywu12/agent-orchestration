# Shared development efficiency

Applies to all current and future projects on this machine. Project instructions, approval boundaries, tests and release gates still apply.

- One lead agent owns the task and integration. Delegate only independent bounded questions or worktrees; avoid automatic all-agent fan-out. Give objective, exact root/SHA, allowed paths, relevant evidence, acceptance check and a short return format. Do not copy the whole conversation. A worker returns result, paths, checks and unresolved risks; the lead owns verification.
- Claude: planning and diagnosis. Codex: implementation, tests and git work. Gemini/Antigravity: targeted review or independent work when requested. Ollama: bounded local analysis with an already installed model. ArkCLI: bounded remote advice using the existing profile and model. Never silently switch models/providers or send credentials/customer data.
- For a new project, run `agent-serena project create /absolute/root --language <language>` once, repeating `--language` for every language requiring symbol lookup (Python + TypeScript for mixed web/backend repos). Preserve existing Serena project settings. Noninteractive auto-detection selects only one language. Before reading large source files, activate the exact absolute worktree using Serena and inspect a symbol outline or references. Request function bodies only when needed. Its shared configuration exposes navigation only. Use ripgrep for literals/configuration and native tools for edits. Do not add another graph/index tool for the same question or perform full-repo onboarding routinely.
- Use `agent-run -- <project-owned check>` for noisy commands. It executes once, retains a private full log, returns the actual status and bounds displayed output. Read the full log whenever a failure needs detail. Use `rtk git status`, `rtk git log`, or `rtk grep` for routine discovery. Use raw Git diffs for final review. Never wrap permission-sensitive commands to evade the host's approval boundaries.
- Load the relevant task-packet section and one existing pattern; keep source of truth in files. Consult advisers with compact evidence only when useful or project-required. Check focused tests while iterating and run required full gates before shipping. Stop speculative retry loops and revise the causal model after two failed fixes.
- `agent-advice --provider ollama --model <installed-model> --prompt-file <brief>` and `agent-advice --provider arkcli --prompt-file <brief>` provide advice, not repository tools. Defaults cap the brief at 16 KiB and generation at 512 tokens. Provider usage is separate from command-output byte measurements. Keep subscription usage, cached input and API spend distinct; optimize cost per accepted task, including retries.
